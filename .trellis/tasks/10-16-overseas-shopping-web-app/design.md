# 技术设计：生活方式精选商品选购 Web 应用

## 1. 目标与边界
以无后端、无登录、无支付的模拟商品目录，完成一条高质量的消费者选购演示路径：发现商品 → 搜索/筛选 → 查看详情 → 加入并管理购物车。首发体验面向美国消费者，使用英文和美元。当前设计不包含服务端架构。

## 2. 技术方案

| 层面 | 选择 | 采用原因 / 边界 |
|---|---|---|
| 应用与构建 | React + TypeScript + Vite；包管理使用 npm | 满足题目 React 要求；无 SEO、SSR 或后端需求，客户端应用更简单，适合静态资源部署。 |
| 路由 | React Router | 对应清晰的首页、商品列表、详情和购物车 URL；详情页支持直接访问；列表搜索/筛选/排序可通过 query string 表示。 |
| 样式 | Tailwind CSS | 快速迭代响应式布局与设计 token；避免大型全局样式耦合。 |
| 基础组件 | 精选 shadcn/ui | 仅复用 Button、Sheet/Dialog、Checkbox、Select 等基础交互组件；业务组件和视觉系统由项目自行实现。不是使用现成商城模板。复制进仓库的组件由项目负责维护。 |
| 动效 | CSS transitions + Motion for React | CSS 覆盖颜色/阴影/基础反馈；Motion 用于面板进入退出、布局变化和加购反馈。动效默认明显、流畅，不做持续无意义装饰或阻塞交互的长过场；提供系统减少动态效果偏好兜底。 |
| 购物车状态 | Zustand + persist middleware + `localStorage` | 在页头、抽屉和购物车页共享状态并在当前浏览器刷新后恢复；不承诺跨设备或跨浏览器同步。 |
| 商品数据 | TypeScript 本地静态数据 | 本地目录与页面展示分离，易于模拟搜索、筛选、排序；数据不伪装成实时库存。 |
| 图片资产 | 本地 Pexels 授权图片 | 避免演示时依赖第三方热链；保存来源、摄影者、下载日期和许可说明。图片作为概念商品视觉示意，不声称为实际商品摄影。 |
| 自动化测试 | 不加入 | 用户明确表示会自行测试。实现仍运行配置好的 lint/typecheck/build 等静态检查，并说明实际手动核验情况。 |

## 3. 页面与路由
- `/`：品牌首页，编辑式 Hero、精选分类/商品、清晰的 Shop CTA。
- `/shop`：商品网格、搜索、筛选、排序。搜索词和筛选/排序状态同步到 URL query string，支持刷新与复制当前列表链接。
- `/products/:slug`：商品详情页，直接访问有效；无效 slug 显示友好 Not Found。
- `/cart`：完整购物车页，支持修改数量、移除、查看小计和继续购物。明确购物流程在购物车结束，不展示不可用的支付承诺。
- 全局 Cart Sheet：从页头或加购反馈打开，快速查看商品并前往完整购物车。弹层仍需具备键盘焦点管理、Esc 关闭和明确关闭按钮。

## 4. 模块与职责边界
建议初始结构，避免过度切分：

```text
src/
  app/                 # Router、全局 Provider、应用级布局
  pages/               # HomePage、ShopPage、ProductPage、CartPage、NotFoundPage
  features/
    catalog/            # 商品卡片/网格、搜索、筛选、排序、列表逻辑
    product/            # 商品详情、变体选择、加购入口
    cart/               # Zustand store、CartSheet、CartItem、购物车汇总
  components/           # 品牌化共享组件，如 SiteHeader、SiteFooter
  components/ui/        # 精选 shadcn/ui 基础组件
  data/                 # 静态商品与分类数据
  lib/                  # 价格格式化、筛选/排序纯函数等通用逻辑
  types/                # Product、Variant、CartItem 等领域类型
  styles/               # Tailwind 入口、全局 token/基础样式
public/images/products/ # 优化后的本地商品示意图
```

单个组件保持单一职责；只对跨页面共享或有独立业务职责的内容抽组件。注释聚焦非显然业务规则、动效退出时序、持久化边界等，不重复解释自明代码。

## 5. 核心数据与状态流

### 商品
`Product` 至少包含 `id`、`slug`、`name`、`category`、`price`（数值 USD）、`images`、`shortDescription`、`material`、`colors`、`rating`、`reviewCount`、`createdAt`、`featuredRank`。商品示例的配送/评价等内容需明确为演示数据，不暗示实时承诺。若变体影响可买配置，使用 `Variant` 表达颜色/尺寸与唯一标识。

### 列表
- 商品数组为唯一目录来源。
- 搜索、筛选、排序在纯函数或 catalog feature 中组合完成，不写入 Zustand 全局购物车 store。
- 当前列表条件读取/写入 URL query string；返回列表时保留状态。
- 品类、价格、颜色、材质为已确认筛选；推荐、上新、价格为已确认排序。

### 购物车
- Cart store 仅保留 `productId`、选中变体标识（若有）、数量及操作方法；显示所需商品详情从静态目录按 id 派生，避免持久化重复数据。
- 操作：add、increment/decrement 或 set quantity、remove、clear。
- 持久化版本化并校验加载数据，若 localStorage 内容损坏或字段失效则安全回退为空购物车；不信任持久化数据的价格，展示金额始终从当前商品目录派生。
- 金额使用 `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })` 格式化；本题只展示商品小计，不计算运费/税费。

## 6. 视觉、响应式与动效原则
- 方向：温暖、中性、克制的编辑式生活方式视觉；产品图优先，排版层级清晰，避免后台风格或通用商城模板感。
- 桌面端发挥宽屏导航、网格与列表筛选；移动端优先单手触达、清晰筛选入口和易关闭的全屏/底部筛选面板。
- 卡片图片使用一致比例；提供合适的 `width`/`height` 或容器 `aspect-ratio`、懒加载非首屏图，降低布局抖动。Hero 主图不应懒加载。
- Motion 优先动画 `transform`、`opacity`；避免高频动画大型 blur、阴影或几何尺寸导致掉帧。动画不可延迟按钮反馈或破坏浏览器返回/焦点。
- 尊重 `prefers-reduced-motion` 可作为无障碍兼容，不改变普通用户默认动效。
- 保持对比度、焦点可见、按钮可键盘访问、输入具有关联 label；抽屉具备焦点管理。

## 7. 图片许可与运行可靠性
- 只从 Pexels 许可允许的素材中下载适合作为演示的家居/生活方式图片；避免可识别品牌商标、误导性人物背书和“真实商品实拍”描述。
- 在 `public/images/products/` 保存压缩后的图片；增加 `assets-credits.md`（素材文件、来源页、摄影者、下载日期、许可链接/说明）。不保留第三方 URL 作为唯一图片源。
- 不抓取零售商商品图片或使用禁止用于竞争服务目录的素材许可。

## 8. 风险与回退
- **图片许可/误导风险：**仅作模拟示意，保持许可记录；若单张许可或来源不清晰则替换，不阻塞构建。
- **localStorage 数据不兼容：**数据解析/版本校验失败时回退空购物车；数据只在本地，不显示虚假云同步。
- **动效性能风险：**默认减少并发复杂效果，优先 compositor 属性；窄屏与低性能设备保持交互可用。
- **静态托管深链接 404：**部署时需配置 SPA fallback 到 `index.html`；本任务优先保证本地 Vite 开发/构建，不承诺部署。
- **组件风格不一致：**仅使用一套 token 和少量 shadcn 基础组件，禁止混入另一套完整 UI 主题。

## 9. 决策记录
- 选择 Vite 而非 Next.js：本题明确不需要 SEO/SSR，降低服务端框架复杂度；若未来要求可索引商品页，重新评估预渲染或 Next.js。
- 选择 shadcn/ui 而非完整主题组件库：更容易拥有品牌视觉与组件源码；代价是团队需自行维护复制的基础组件。
- 选择本地持久化而非内存状态：刷新体验更符合购物车预期；限制是没有跨设备同步。
- 不做结账/自动化测试：优先完成题目核心的发现、详情和购物车流程；用户自行进行最终测试。
